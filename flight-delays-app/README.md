# Анализ задержек авиарейсов

Веб-приложение (клиент-сервер) по проекту «Анализ перелётов. Как зависит задержка рейсов от времени вылета»:
показатели пунктуальности авиакомпаний, зависимость задержек от времени вылета, результаты статистического анализа
(корреляция Спирмена, хи-квадрат, Краскел — Уоллис и Данн, регрессия), отчёты, роли и администрирование.

## Как устроено

Система разделена на два контура — так тяжёлые расчёты не выполняются при каждом открытии страницы.

- **Офлайн-конвейер** (`backend/pipeline`, Python + pandas/scipy). Читает исходные CSV с рейсами, чистит данные,
  строит агрегаты, считает статистические критерии и регрессионные модели и записывает **готовые результаты** в PostgreSQL.
  Запускается вручную при загрузке или обновлении данных.
- **Онлайн-приложение** (`backend` — FastAPI, `frontend` — React). Работает только с агрегатами и готовыми результатами:
  не держит в памяти миллионы строк и не требует pandas на сервере.

```
Браузер (React SPA) ── HTTPS ── Caddy ──┬── статика интерфейса
                                         └── /api → FastAPI ── PostgreSQL
Офлайн: CSV → pipeline → агрегаты, критерии, модели → PostgreSQL
```

Стек: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 16, argon2 + JWT в HttpOnly-cookie, openpyxl/ReportLab/matplotlib
(отчёты), React 18 + TypeScript + Vite, Mantine, Apache ECharts, TanStack Query, Docker Compose, Caddy.

```
backend/
  app/            API: авторизация, статистика, методы, отчёты, администрирование
  pipeline/       офлайн-конвейер: очистка, агрегаты, критерии, регрессия, запись в БД
  alembic/        миграции схемы БД
  tests/          68 тестов (SQLite и PostgreSQL)
frontend/
  src/            страницы, графики, работа с фильтрами и API
  src/test/       тесты интерфейса на реальных снимках ответов API
deploy/           Caddyfile и Dockerfile веб-части
docker-compose.yml, .env.example
```

## Роли и права

Роли иерархичны: каждая следующая включает права предыдущей. Права проверяются **на сервере**; скрытие кнопок в интерфейсе — только удобство.

- **Гость** — лендинг с главными выводами (считаются из данных), регистрация и вход.
- **Пользователь** (роль по умолчанию после регистрации) — панель показателей: фильтры по авиакомпании, аэропорту, периоду и
  времени вылета; порог задержки (> 0 мин или ≥ 15 мин); средняя задержка по всем рейсам или только по задержанным;
  рейтинг авиакомпаний с доверительными интервалами; анализ по часам, периодам суток, дням недели, месяцам и аэропортам;
  категории задержек; сравнение двух авиакомпаний; профиль и смена пароля.
- **Аналитик** — всё перечисленное, а также раздел «Методы анализа», отчёты в Excel и PDF с графиками, выгрузка таблиц в CSV,
  сохранённые наборы фильтров.
- **Администратор** — всё перечисленное, а также пользователи (роль, блокировка, удаление), журнал действий,
  справочники авиакомпаний и аэропортов, сведения о загруженных данных. Роль выше «пользователя» назначает только администратор.

## Быстрый старт для разработки (без Docker)

Нужны Python 3.12 и Node.js 22.

```bash
# 1. Бэкенд
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env                                   # SQLite, администратор admin@example.com / Admin12345
python -m pipeline.run --demo --create-tables          # ДЕМО-данные (синтетические), ~1 минута
uvicorn app.main:app --reload --port 8000

# 2. Интерфейс (в другом терминале)
cd frontend
npm ci
npm run dev                                            # http://localhost:5173, запросы /api проксируются на :8000
```

Документация API: http://localhost:8000/api/docs. После `--demo` в шапке появляется оранжевая полоса
«Демонстрационный режим» — все значения смоделированы, авиакомпании вымышлены.

## Загрузка реальных данных

```bash
cd backend
python -m pipeline.run --csv Combined_Flights_2021.csv Combined_Flights_2022.csv
```

Конвейер читает файлы порциями, поэтому память расходуется умеренно. Повторный запуск **заменяет** агрегаты и результаты анализа;
названия авиакомпаний и аэропортов, исправленные администратором, сохраняются.

**Формат CSV.** Столбцы определяются по именам. Поддерживаются наборы Kaggle `Combined_Flights_2021/2022` (`FlightDate`, `Airline`,
`Origin`, `CRSDepTime`, `ArrDelayMinutes`, `Cancelled`, `Diverted`, `CRSElapsedTime`, `OriginCityName`, `OriginState`) и `2015 Flight Delays`
(`YEAR/MONTH/DAY`, `AIRLINE`, `ORIGIN_AIRPORT`, `SCHEDULED_DEPARTURE`, `ARRIVAL_DELAY`, …). Если у ваших файлов другие имена,
конвейер перечислит найденные столбцы и остановится; сопоставьте вручную: `--map airline=Carrier --map origin=Dep_Airport`
(логические поля: `date`, `year`, `month`, `day`, `airline`, `origin`, `origin_city`, `origin_state`, `sched_dep`, `arr_delay`,
`cancelled`, `diverted`, `duration`). Список имён по умолчанию — в `backend/pipeline/columns.py`.

**Что делает конвейер**

1. Приводит время к виду «час планового вылета» (местное время аэропорта; 2400 → 0), отбрасывает строки без даты, времени,
   авиакомпании или с числовым кодом аэропорта вместо IATA (их число сохраняется и видно администратору).
2. Исключает отменённые и перенаправленные рейсы из расчёта задержек (их число сохраняется отдельно).
3. Строит агрегаты `авиакомпания × аэропорт вылета × месяц × день недели × час` с числом рейсов, задержанных (> 0 и ≥ 15 минут),
   суммами минут, максимумом и категориями задержки.
4. На случайной выборке (по умолчанию 12% рейсов, не более 1,2 млн) считает Спирмена, Краскела — Уоллиса, парные сравнения Данна
   (поправка Бонферрони) и регрессионные модели; хи-квадрат считается по всем рейсам. Модели оцениваются на отложенной части (1/3).
5. Записывает всё в БД в одной транзакции: либо всё, либо ничего.

**Определения (проверьте, что они совпадают с вашим отчётом):**
- задержка — опоздание **прибытия** в минутах, досрочное прибытие равно 0;
- «задержан» — опоздание больше 0 минут; второй порог — **15 минут и более** (стандарт FAA/BTS);
- периоды суток по местному времени вылета: ночь 00–05, утро 06–11, день 12–17, вечер 18–23 (`backend/app/domain.py`);
- категории: 0; 1–15; 16–30; 31–60; 61–120; более 120 минут;
- размеры эффекта: ρ — до 0,1 / 0,3 / 0,5; V Крамера — 0,1 / 0,3 / 0,5; ε² — 0,01 / 0,06 / 0,14 (`pipeline/labels.py`).

**Размер.** На 4 млн демо-рейсов получилось ~1 млн строк агрегатов (154 МБ с индексами), конвейер отработал за ~100 секунд на одном ядре.
Для 10 млн реальных рейсов ожидайте порядка 2–3 млн строк агрегатов (оценка, не измерение) — это нужно учесть при выборе тарифа БД.

## Запуск в Docker

```bash
cp .env.example .env        # задайте POSTGRES_PASSWORD, SECRET_KEY, FIRST_ADMIN_PASSWORD
docker compose up -d --build
# данные: положите CSV в ./data и выполните
docker compose --profile pipeline run --rm pipeline --csv /data/Combined_Flights_2021.csv /data/Combined_Flights_2022.csv
# или для проверки: docker compose --profile pipeline run --rm pipeline --demo
```

Сайт: http://localhost. При старте бэкенд применяет миграции и создаёт первого администратора из `FIRST_ADMIN_*`
(если администраторов ещё нет; значения-заглушки `CHANGE_ME…` отклоняются). После первого входа смените пароль и удалите
`FIRST_ADMIN_PASSWORD` из `.env`.

## Публичный хостинг (VPS)

1. Сервер с Docker и Docker Compose, открытые порты 80 и 443, доменное имя с A-записью на сервер.
2. В `.env`: `SITE_ADDRESS=ваш.домен`, `COOKIE_SECURE=true`, `APP_ORIGINS=https://ваш.домен`, надёжные `SECRET_KEY` и `POSTGRES_PASSWORD`.
3. `docker compose up -d --build` — Caddy сам получит и будет продлевать сертификат Let's Encrypt.
4. Загрузите данные командой из предыдущего раздела.
5. Резервная копия: `docker compose exec -T db pg_dump -U flights flights | gzip > backup.sql.gz`.
6. Обновление: `git pull && docker compose up -d --build` (миграции применяются автоматически).

Бесплатные тарифы облачных БД обычно ограничены сотнями мегабайт — проверьте лимиты до выбора хостинга.

## Безопасность

- Пароли хешируются argon2; требования: от 8 символов, буквы и цифры. Сессия — JWT в HttpOnly-cookie (SameSite=Lax, Secure по флагу);
  смена пароля мгновенно отзывает все прежние сессии; блокировка и смена роли действуют сразу.
- Защита от перебора: 5 неудачных входов блокируют учётную запись на 15 минут; ограничение частоты запросов по IP (вход — 10/мин,
  регистрация — 5/мин, экспорт — 10/мин).
- CSRF: cookie SameSite=Lax, изменяющие запросы принимаются только с «своего» Origin, тело — только JSON.
- Заголовки безопасности и CSP выставляет Caddy; параметры фильтров валидируются; SQL — только через ORM.
- Журнал действий: вход, неудачные входы, экспорт, изменения пользователей и справочников.

## Тесты

```bash
cd backend && pytest -q                                   # SQLite
TEST_DATABASE_URL=postgresql+psycopg://user:pass@localhost/test pytest -q   # PostgreSQL (таблицы пересоздаются!)
cd frontend && npm run typecheck && npm test && npm run build
```

Бэкенд-тесты сверяют ответы API с независимым расчётом по сырым данным (pandas), проверяют роли, блокировку, журнал, отчёты
и сравнивают собственные реализации МНК и логистической регрессии со statsmodels. Тесты интерфейса используют реальные снимки
ответов API и строят все графики серверным рендером ECharts. CI (`.github/workflows/ci.yml`) запускает всё на SQLite и PostgreSQL.

## Ограничения и допущения

- Регрессия показывает **связь**, а не причины: погоды, загрузки аэропортов и задержки предыдущего рейса в данных нет.
- Ограничитель частоты запросов и кэш хранятся в памяти процесса: при нескольких процессах лимиты применяются на каждый
  процесс отдельно (для строгих лимитов задайте `RATE_LIMIT_STORAGE_URI=redis://…` и добавьте пакет `redis` в `requirements.txt`).
- Сессия — JWT без серверного хранилища: «Выйти» удаляет cookie, но скопированный токен действует до истечения (8 часов)
  или до смены пароля.
- Регистрация открыта для всех; подтверждение email не реализовано.
- Образы Docker и `docker-compose.yml` не собирались в среде, где проект подготовлен; проверены синтаксис compose и боевой
  Caddyfile, а приложение проверено на PostgreSQL 16 и за Caddy с теми же заголовками.
